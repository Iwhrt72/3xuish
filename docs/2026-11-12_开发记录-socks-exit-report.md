由 E6、E7、E8 得到本次已验证的配置结论 F1：将入口全部流量直接转发给这条 SOCKS5 出口，会使交给该出口处理的 UDP DNS 失败。对应处理路径 P1 为“入口 UDP/53 → Xray DNS 出口 → TCP DNS → 该入口专属 SOCKS5 出口 → 解析器”。这一结论限定在 DNS 路径；用户报告的所有手机端失败仍需实际手机复测闭环。

前面的回答曾过早把故障归于 NekoBox 1.4.2，也曾直接建议换客户端。后续证据表明，应分别记录客户端握手兼容问题与服务器 DNS 转发问题，不能用一项测试概括用户的全部症状。

**实现方案及代码位置**

本次采用 VLESS TCP + TLS + Vision 作为新入站，复用现有 TLS 证书。选择这个方案时没有再要求用户额外选择协议，这是实现决定。原来手工创建的 REALITY/26560 节点没有由新命令原位改造。

| 文件 | 本次职责 |
|---|---|
| `install.sh` | 增加菜单第 12 项、`--add-socks-node` 分发、维护锁及辅助组件下载与哈希校验 |
| `install_3xui_xhttp_vlessenc.sh` | 与主安装入口保持字节一致 |
| `lib/socks_exit.sh` | 交互输入、出口预检、模板合并、禁用入站创建、启用、回滚与结果输出 |
| `lib/socks_node_probe.py` | SOCKS5 认证、HTTPS 出口 IP、TCP DNS、临时 Xray 客户端 UDP DNS 验证 |
| `tests/test_socks_exit_provision.py` | 9 项路由合并与冲突保护测试 |
| `README.md` | 新命令、适用范围、TLS 证书前提和运行影响说明 |

命令在已安装 3x-ui 的 VPS 上运行。菜单读取四项代理资料，密码不回显。面板认证沿用原项目的 `api_init()`，新功能不要求再次填写面板账号密码。该认证流程可通过面板 CLI 获取安装器专用管理员令牌。

每个新节点有独立的 SOCKS 出口及 DNS 出口，路由只匹配该节点的 `inboundTag`。DNS 出口使用 `rewriteNetwork: "tcp"`、`rewriteAddress: "1.1.1.1"`、`rewritePort: 53`，并通过 `streamSettings.sockopt.dialerProxy` 绑定到该节点的 SOCKS 出口。早期试验使用的 `proxySettings` 已被当前 Xray 移除，实际方案已改用 `dialerProxy`。

采用逐节点 TCP DNS，是为了让多个出口各自处理对应节点的 DNS，不依赖一份全局 DoH 配置绑定单一出口。上游必须允许实测 DNS 服务的 TCP/53。命令当前接收 SOCKS5 代理，HTTP 代理及所有 UDP 应用支持仍在本次实现范围之外。

新节点身份标签由 IP、端口、账号和密码的组合计算摘要后生成，标签不包含明文密码。同一组合重复执行会被拒绝，密码发生变化会形成另一个身份。这个检查是防重复创建，尚未实现完整的“更新现有节点凭据”或“断点恢复”模式。

**创建和回滚流程**

1. 校验输入，实测上游 SOCKS5 的 HTTPS 和 TCP DNS，记录预期出口 IP。
2. 读取现有面板信息、证书和 Xray 路径，通过 API 认证并检查冲突。
3. 从 TCP/26600 起选择空闲端口，生成新客户端身份、入站及专属出口计划。
4. 将新配置与现有运行配置合并，用实际 Xray 核心执行 `run -test`。
5. 通过 SQLite backup API 创建一致性备份，权限设为 0600。
6. 用 `/panel/api/inbounds/add` 创建 `enable=false` 的入站，再回读实际 ID、tag 和禁用状态。
7. 重新读取面板模板，核对会被写回的配置并合并出口与路由。
8. 向 `/panel/api/xray/update` 提交表单字段 `xraySetting` 与 `outboundTestUrl`，再回读确认。
9. 调用 `/panel/api/inbounds/setEnable/:id` 启用节点，检查运行配置和监听端口。若未生效，调用 `restartXrayService` 后复查。
10. 启动临时本地 Xray 客户端，经新 VLESS 节点测试 UDP DNS 和 HTTPS，并核对实际出口 IP。通过后才打印成功。

模板合并保留原有出站及规则，并将两条新入站专属规则插入受支持的全局兜底规则之前。既有更早的匹配规则仍按顺序生效，因此任意自定义路由环境仍需检查实际命中结果。

失败补偿先尝试删除本次入站，确认删除后再按本次标签清理出站和路由。无法确认入站已删除时，脚本保留相应规则并输出警告，以防残留入站误用默认出口。回滚写模板后没有独立的完整运行状态验收，仍依赖面板应用结果。SQLite 备份是恢复依据，不能据此承诺所有中断场景均自动恢复。
