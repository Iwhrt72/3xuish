# 四种节点的性能对照

本次优化来自一次真实客户端链路的下载对照。数据用于说明默认方案为何调整，不能作为其他服务器或运营商的速度保证。

## 怎样控制测试条件

测试使用同一台服务器、同一台电脑、同一个下载文件和相同客户端内核。每段下载最多 20 秒，文件上限为 100MiB。

核心对照采用 **XHTTP → RAW TCP → XHTTP**，三段保持同一个服务器 IP 和 TCP `443` 端口。切换传输时，TLS 证书、ALPN、Vision、VLESS Encryption 和 socket 参数均保留。

另外建立 REALITY 的 TCP 入口和 Hy2 的 UDP 入口，对比其他实际可用方案。它们同时改变了端口及其他协议设置，因此不属于只改变一个变量的实验。

## 观察到的结果

| 测试 | 平均下载速度 |
| --- | ---: |
| XHTTP，切换前 | 5.63Mbps |
| RAW TCP + TLS，同一 TCP 443 | 25.67Mbps |
| XHTTP，恢复后 | 5.33Mbps |
| VLESS + REALITY | 22.22Mbps |
| Hy2 | 48.74Mbps |

RAW TCP 的速度约为前后两次 XHTTP 均值的 **4.7 倍**。恢复 XHTTP 后速度再次下降，说明在这套配置、客户端和链路条件下，XHTTP 相关传输行为是瓶颈之一。

Hy2 在这一轮最快，约 17.2 秒下载完整个 100MiB 文件。其余四段已获得 HTTP `200` 和下载数据，随后因 20 秒采样期限结束而返回 curl 退出码 `28`；这与连接建立失败不同。

## 能得出什么结论

- 原来的 XHTTP 单节点默认方案不适合这次客户端链路，值得提供多个可切换方案。
- RAW 和 XHTTP 保留了同一份证书，域名证书类型不能解释这次速度差异。
- Hy2 可以作为默认主用候选，REALITY 和 RAW TCP 可以保留为 TCP 备用，XHTTP 继续用于兼容和对照。
- 最终主用方案应由用户根据自己的接入网络选择；安装菜单只改变推荐标记和链接顺序，不删除备用节点。

## 仍不能据此判断什么

一次短时测试无法区分 HTTP/2 流控、客户端实现、复用行为或中间网络对流量形态的处理，也不能证明 XHTTP 在所有网络中都慢。

RAW 和 REALITY 仍只有约 22–26Mbps，Hy2 也未接近套餐标称 `1Gbps`。还可能存在共同线路、服务商互联或端到端带宽限制。UDP、端口和拥塞控制在 Hy2 对照中同时发生变化，不能把全部提升归因于其中一项。

调低 TLS 最低版本是显式兼容配置，不是这轮实验单独验证过的修复因素。主用节点也不应在没有客户端实测时被称为“自动测速选出的最快节点”。

## 自己复测时

保持客户端、下载源、测试时长和接入网络一致，一次只改一个因素。比较 TCP 方案时尽量控制端口差异；必要时用“原方案 → 新方案 → 原方案”的顺序排除部分时间波动。

如果 Hy2 无法连接，先确认 UDP 端口能通过安全组、防火墙及接入网络，再判断性能。若测试下载得到的是 HTTP 错误页，应停止使用该次速度结果。
