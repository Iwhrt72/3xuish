# 3x-ui 面板升级设计与验证

记录日期：2026-11-12（America/Los_Angeles）。功能入口为菜单23 / `--update-panel`，结果入口为菜单24 / `--panel-update-status`。本次开发在本地与一次性容器中验证，没有执行生产服务器升级。

## 升级范围

菜单12负责 Xray 核心，菜单23负责3x-ui面板。面板升级使用官方稳定发行包中的主程序和管理脚本，保留现有 `bin` 中的核心与GeoIP文件、服务配置、节点、客户端、管理员账号、证书及订阅。不会再次运行四节点创建流程。

默认支持原生SQLite布局 `/usr/local/x-ui`、`/etc/x-ui/x-ui.db`、`x-ui` 服务，适配systemd/OpenRC。容器、外部数据库、自定义服务及路径、跨文件系统恢复布局会在修改前拒绝。保留这些边界是为了确定实际服务、数据库和恢复目标一致。

## 升级事务

1. 取得共享维护锁，检查其他创建、修复、重装或升级任务是否尚未完成。
2. 将任务实现快照到 `/root/3xuish-panel-update/job-*`，以独立会话执行；前台断连不会终止后台。
3. 通过官方 `releases/latest` 查询稳定版，与 `x-ui -v` 比较。同版或本机版本更新时不下载发行包，不停止服务，不降级。
4. 下载目标架构的发行包，核对官方SHA-256及大小，限制解包资源并拒绝路径穿越、链接和特殊文件；检查候选ELF、CLI语法和版本。
5. 检查有效服务配置、数据库环境、现有身份、实际监听、核心摘要和备份恢复所需空间。
6. 停止服务并确认面板及核心进程静止，备份程序目录、数据库目录和管理命令；SQLite backup保证已提交WAL内容进入独立备份。
7. 替换面板主程序和官方CLI，保留服务定义及现有核心，启动并验证版本、面板HTTP/HTTPS、原监听与身份数据。
8. 验收失败时先停止新程序，恢复旧程序与旧数据库，再验证原服务；恢复无法确认则记录人工恢复状态，禁止继续脚本维护。

任务、备份和日志均位于root私有目录。中文状态区分“无需升级”“升级完成”“已恢复旧版”和“需要人工检查”，结构化状态可用 `--json` 查询。数据库迁移失败不能只回退二进制，所以恢复路径必须包含数据库与WAL处理。

## 发布包依据

开发时官方最新稳定版为v3.11.0，程序使用动态查询，不把此版本写死。实际验证了官方amd64归档及其SHA-256；包内包含面板程序、管理脚本、service模板和核心资源。本功能不盲目执行远程 `install.sh`，也不替换用户已选择的核心。

官方来源：[最新稳定发布API](https://api.github.com/repos/MHSanaei/3x-ui/releases/latest)、[发布构建流程](https://github.com/MHSanaei/3x-ui/blob/v3.11.0/.github/workflows/release.yml)、[CLI实现](https://github.com/MHSanaei/3x-ui/blob/v3.11.0/main.go)。

## 验证入口与边界

```bash
python3 scripts/sync_socks_helpers.py --check
python3 -m unittest discover -s tests -v
```

`test_panel_release.py` 覆盖版本、架构、下载摘要、官方地址限制和危险归档。`test_panel_upgrade.py` 覆盖后台锁与断连、同版本跳过、失败补偿、数据库迁移与WAL恢复。`test_panel_upgrade_entrypoint.py` 及维护测试覆盖菜单分发和未完成任务保护。

`panel_upgrade_smoke.py` 在一次性官方容器中使用真实面板、HTTPS入口、数据库和Xray，仅替换容器中不存在的服务管理器。当前最新发行版与CI镜像均为v3.11.0，因此真实事务测试验证同版本候选的替换、健康核对与模拟数据库迁移后失败恢复；不把它描述为已完成跨版本生产迁移。生产CLI的同版本路径仍然直接跳过，不提供强制重装开关。

## 本次验证结果

本地完整Linux套件317项通过，0失败、0跳过；最后补充的环境配置解析修正又分别通过Linux与Windows的24项升级专项测试（Windows跳过2项POSIX用例）。发行包模块19项测试通过，覆盖下载前和解包前的低磁盘拒绝。

真实官方归档及固定官方镜像两种候选路径均运行成功。HTTPS面板、实际订阅、客户端UUID、管理员账号、端口、Xray摘要和服务配置均核对；失败路径实际改动了SQLite表结构、用户名及统一订阅外链，随后验证旧程序、旧数据库和真实订阅内容恢复。已是最新版时确认没有调用服务停止或启动。临时容器已清理，生产服务器未执行升级。

升级前还拒绝会重定向数据库的 `.env` 赋值，包括YAML式冒号、引号内或路径内的 `#`、插值和无法明确解释的表达式，避免备份与实际服务使用不同数据库。
